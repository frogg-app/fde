The desktop app is a client. It connects to daemons you install separately, on the same
computer or elsewhere, and never starts, bundles or stops a daemon. Closing it leaves
agents running.

## Download

From [GitHub releases](https://github.com/frogg-app/frogg/releases/latest):

| Platform | Files |
| -------- | ----- |
| Windows x64 | `Frogg-<version>-win-x64.exe` (one-click installer, per-user), `Frogg-<version>-win-x64.zip` (portable), `Frogg-<version>-win-x64-installer.zip` (the installer, zipped for browsers that block `.exe`) |
| macOS    | `Frogg-<version>-mac-arm64.dmg` (Apple silicon), `Frogg-<version>-mac-x64.dmg` (Intel), plus `.zip` |
| Linux x64 | `Frogg-<version>-linux-x86_64.AppImage`, `Frogg-<version>-linux-amd64.deb`, `Frogg-<version>-linux-x64.tar.gz` |

macOS builds are not notarized, and Windows builds may be unsigned. See
[install](/docs/getting-started/install/#2-install-a-client) for the first-launch steps.

### Windows installer

The Windows installer has no wizard. Double-click it and a small window shows install
progress, then the app opens. It installs for the current user under
`%LOCALAPPDATA%\Programs\<name>` and needs no administrator rights. An existing per-user
install is updated in place, in its current folder.

<Screenshot src={installerProgress} alt="Windows installer showing install progress" />

If an older release is installed for all users (for example under `C:\Program Files`), the
installer removes it first so you do not end up with two copies:

1. Windows asks once for administrator approval to run the old uninstaller.
2. The old copy and its all-users shortcuts are removed. App data in `%APPDATA%` is kept.
3. The app is installed for your account.

If you decline the prompt, the installer offers to retry and otherwise stops with the old
copy untouched. Automatic updates take the same path, so the first update of an all-users
install shows the administrator prompt once.

<Screenshot src={installerMigrating} alt="Windows installer moving an all-users install to the current account" />

For scripted installs, run the installer with `/S`. Add `/D=<folder>` (last argument) to
choose the install folder.

:::note
Upgrading from the pre-0.6 desktop app (the Tauri shell) is manual: install the new app
and add or re-pair your hosts.
:::

## Connect to daemons

**Hosts** in the sidebar adds connections. The desktop app supports every method, including
**Remote SSH**. One window can use several hosts at once; each project belongs to one host.

## Remote SSH

Remote SSH reaches a daemon through your system OpenSSH client, so it honours
`~/.ssh/config`: users, ports, keys, agents and jump hosts. The app picks hosts from your
SSH config or takes `user@host`.

- The connection forwards stdio to `127.0.0.1:<daemon port>` on the remote host (default
  9999). The daemon does not need to be reachable on the network.
- If the host refuses your keys but allows passwords, the app asks for the SSH password.
  It is kept in memory only.
- A separate **daemon password** field is for daemons with a password; it is saved with the
  host.

### Deploy a daemon over SSH

If SSH works but no daemon answers, the app offers to **Deploy** one. You can also deploy
from the host's settings.

1. The app probes the host: OS, architecture, Docker, systemd user services, `curl`, and
   any existing install.
2. It pipes the same `install.sh` (or `install-docker.sh`) you would run by hand over SSH.
   Nothing is uploaded: the host downloads the release bundle from GitHub itself.
3. It installs the version that matches the app, listening on `0.0.0.0:9999` by default.
   Choose `127.0.0.1` to keep the daemon reachable only through SSH.
4. The log streams into the dialog, and the connection retries when the install finishes.

The same screen can **uninstall** the daemon. Daemon state in `~/.frogg` is kept.

Remote hosts need Linux or macOS with `bash` and `curl`, and outbound access to GitHub.

## Updates

The app checks GitHub releases and downloads updates in the background, then installs
them when you quit. On Windows the update runs the installer silently; an all-users install
from an older release asks for administrator approval once while it moves to your account
(see [Windows installer](#windows-installer)).

- Channel: **Stable** (default) or **Beta**, in settings.
- AppImage installs do not update on quit; download the new AppImage.
- A release can require a manual upgrade from very old clients; the app says so.
- Unpackaged development builds never update.

Updating the app does not update your daemons. Update each daemon from its host settings
or with `frogg update`; see [updates](/docs/self-hosting/updates/).

## Open projects and links

- `frogg .` (or any directory) on the command line opens that directory as a project in the
  desktop app.
- `frogg://` links open the app: agent links (`frogg://h/<serverId>/agent/<agentId>`) and
  pairing links (`frogg://pair#offer=...`).
- Launching the app again focuses the running instance.

## Notifications

Agents that finish, fail or need a permission raise system notifications. Clicking one
focuses the window that sent it.

## Also in the desktop app

- **Open in editor** for files and workspaces (VS Code, Cursor, Zed, JetBrains IDEs and
  others it detects).
- A built-in browser panel for workspace services.
- Network scan for daemons on the LAN in **Direct connection**.

Window headers remain draggable when both sidebars are open; settings-modal headers
do not drag the window. The explorer close toggle sits in the active panel toolbar
for Files, Changes, Diff and Pull Request panels.

The home screen displays a large brand mark above the project actions. Frogg taskbar
and dock icons use tightly framed artwork with a small transparent margin to avoid clipping.

There is no system tray icon. On Windows and Linux, closing the last window quits the app.
