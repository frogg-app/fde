## Model

- A **project** is a directory you registered on a daemon, usually a git repository.
  IDs look like `prj_a00e87f3186c7681`.
- A **workspace** is one working directory inside a project: the original checkout, a git
  worktree, or a plain directory. Agents, terminals and scripts run in a workspace. IDs
  look like `wks_b5b04560aaa0b892`.
- Projects and workspaces belong to one daemon and are stored in
  `~/.fde/projects/`.

## Add a project

- App: **Add project** in the sidebar, then choose a folder on the daemon host.
- CLI: `fde project create /path/to/repo`.

Import existing Claude Code or Codex sessions with **Import session** on the home screen.

## Workspaces and worktrees

When you start work you choose **isolation**:

| Isolation  | What you get |
| ---------- | ------------ |
| `local`    | The agent works directly in the checkout |
| `worktree` | FDE creates a git worktree on a new or existing branch; your checkout stays untouched |

Worktree modes:

| Mode              | Creates |
| ----------------- | ------- |
| `branch-off`      | A new branch from a base ref (`--base`) |
| `checkout-branch` | A worktree for an existing branch |
| `checkout-pr`     | A worktree for a pull request or merge request (`--pr-number`, `--forge`) |

```sh
fde workspace create --isolation worktree --mode branch-off --new-branch feature/export
fde agent run --new-workspace worktree --new-branch fix/flaky-test "Fix the flaky upload test"
```

Worktrees live under `~/.fde/worktrees/<project hash>/<slug>`. Change the root with
`worktrees.root` in [config](/docs/reference/configuration/#worktrees). If you do not
name a branch, FDE can generate one from the first prompt.

Archiving a workspace removes its FDE-owned worktree once nothing else uses it:

```sh
fde workspace archive wks_b5b04560aaa0b892
```

## Prepare new worktrees

A fresh worktree has no `node_modules`, `.env` or build output. Describe setup in
`fde.json` at the repository root:

```json title="fde.json"
{
  "worktree": {
    "setup": ["npm ci", "cp \"$FDE_SOURCE_CHECKOUT_PATH/.env\" .env"],
    "teardown": "docker compose down"
  }
}
```

The app nudges you with **Set up worktree scripts** until a project has setup commands.

## Scripts and services

`fde.json` scripts run in a workspace. A **service** gets its own port, env vars and a
proxy URL, so the same dev server can run in several worktrees at once.

```json title="fde.json"
{
  "scripts": {
    "api": { "type": "service", "command": "npm run dev -- --port $FDE_PORT" },
    "test": { "command": "npm test" }
  }
}
```

```sh
fde script start api
fde script ls
```

Full reference: [project config](/docs/reference/project-config/).

## Terminals

Each workspace can have terminals in the app. The CLI and agents can drive them too:

```sh
fde terminal create --name build
fde terminal send-keys <terminal-id> "npm run build" Enter
fde terminal capture <terminal-id> --scrollback
```

## Labels and archiving

- Workspaces can be renamed (`fde workspace rename`) and labelled in the app.
- Archived agents and workspaces disappear from the sidebar but keep their history.
  `fde agent ls -a` includes archived agents.
