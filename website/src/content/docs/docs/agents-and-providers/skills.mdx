Skills are instruction files that teach agents to use Frogg through the `frogg` CLI:
creating agents, handing off work, running schedules. The daemon ships a bundle and
installs it into the skill directories agent CLIs read.

## Where they go

On the daemon host, the selected skills are copied to:

- `~/.agents/skills/`
- `~/.claude/skills/`
- `~/.codex/skills/`

Custom brands prefix the directory names, for example `acme-frogg-handoff`, so two products
never overwrite each other's skills.

## Manage

**Host settings → Agents → Orchestration skills** shows whether the installed copies are
up to date, and lets you update, choose or uninstall them. Uninstall removes only the
skills Frogg manages.

Choose a subset in config:

```json title="~/.frogg/config.json"
{ "agents": { "skills": { "selection": { "mode": "custom", "skills": ["frogg", "frogg-handoff"] } } } }
```

`{ "mode": "all" }` (the default) follows the bundle as it gains skills. Reload agents
afterwards (`frogg agent reload <id>`) so they see changes.

## The bundle

| Skill               | Use |
| ------------------- | --- |
| `frogg`               | Reference for managing projects, workspaces, scripts, agents, schedules and heartbeats through the CLI |
| `frogg-handoff`       | Hand the current task to another agent with full context |
| `frogg-advisor`       | Ask a single agent for a second opinion |
| `frogg-committee`     | Two high-reasoning agents do root-cause analysis and produce a plan |
| `frogg-help`          | Answer questions about Frogg setup, configuration and troubleshooting |
| `frogg-dev`, `frogg-docs`, `frogg-i18n`, `frogg-rpc`, `frogg-release`, `frogg-build-monitor` | Working on the Frogg repository itself |

Invoke a skill in the composer with `/` or by describing the task; the agent CLI decides
when a skill applies.
